# X13: custom and bundled fonts registered at launch, the fonts folder followed

GPUI does (file:line), and what the Swift app does now. A line is ticked only after it ran: `ffi` = real-FFI Rust test,
`swift` = real-core Swift test (`SettingsBridgeTests/FontFolderTests`), `run A/B/C` = a `--background` instance
(transcripts `X13-run-a.txt`, `X13-run-a2.txt`, `X13-run-b.txt`, `X13-run-c.txt`; shots beside this file; test font Inter,
not installed on this Mac, copied from outside the repository into the instance's `fonts/`).

## At launch
- [x] The fonts folder is scanned and every font that parses is registered for the process before the first window
      (`fonts.rs:48 init`, `:106 register_all`, `platform/macos/fonts.rs:86`). run A1: instance started with Inter in `fonts/` and
      `font_family=Inter`, Settings never opened: `fonts ... resolved=Inter`, `1-launch-inter.png`. (Before this change the picker
      registered them, so the same start drew a fallback.) swift: `testAFontIsRegisteredAtStartAndFollowedAsTheFolderChanges`.
- [x] Core decides what a font file is (extensions, depth, parse) and Swift only calls CoreText: `font_folder_changes` over
      `custom::fingerprint/changes/read_font_file`. ffi: `fonts_follow::tests::*`.
- [x] A file that is not a font is skipped and never stops the others (`fonts.rs:106-109`). ffi: `a_file_added_changed_and_removed...`;
      run A7: `Broken.ttf` beside Inter, `resolved=Inter`.
- [x] The bundled family is registered at launch unless a custom font of the same family replaces it (`fonts.rs:55-69`). run A8:
      `font_family=JetBrains Mono` is `files(...)` (bundled) until a custom `JetBrainsMono-Regular.ttf` is put in the folder, then
      `system(family: "JetBrains Mono") resolved=JetBrains Mono`, and `files(...)` again once it is removed.
      (GPUI applies a replacement after a restart; Swift applies it live.)
- [x] The bundled family is registered before text is shaped: `SettingsBridge.make` hands `platform.bundledFonts()` to the backend,
      which registers them with the first look at the folder (run B: ui_font_family=JetBrains Mono draws in it with no terminal font set).

## While running (`fonts.rs:75 poll_custom`)
- [x] A font added to the folder is registered and the terminals redraw in it. run A3: `resolved=Helvetica` -> `Inter`, `3-added-inter.png`
      equals `1-launch-inter.png`. ffi: `the_fonts_folder_is_followed_and_each_change_is_reported_once` (a real wake). swift: same test.
- [x] A font removed is unregistered and the terminals fall back. run A2: `resolved=Helvetica`, `2-removed-fallback.png` (glyph shapes
      and cell width change). swift: `installed("JetBrains Mono")` false after the file is deleted. (GPUI's `CTFontManagerUnregisterFontsForURL`
      answers "not registered" for a file already deleted and ignores it, so there the face stays until a restart; here the font is
      registered from its bytes (`CGFont`) so it can be dropped without the file. Collections (`.ttc/.otc`) stay registered by path and are
      dropped only while their file is there.)
- [x] A file replaced by another is dropped and read again (`poll_custom`'s `removed`/`added`, GPUI says "after a restart"). run A4:
      Inter Regular bytes replaced by Inter SemiBold, `4-replaced-semibold.png` shows the heavier face with the new cell width.
- [x] The interface font (`ui_font_family`) follows the folder: run B: config names Inter, folder empty -> system face
      (`5-ui-1-empty.png`), file copied in -> Inter (`5-ui-2-added.png`), removed -> system (`5-ui-3-removed.png`), added again -> Inter
      (`5-ui-4-readded.png`); crops of the sidebar row compared byte for byte (047d4a78 / cb052bfb / 047d4a78 / cb052bfb).
      Needed a change of how a family is looked up: SwiftUI and AppKit keep the answer for a font name, so `TextRole.font` and
      `CodeFont.font` ask CoreText each time (`CTFont.face(of:size:)`).
- [ ] The code font (`code_font_family`, diff and viewer) redraws on a folder change: the value moves with the same revision
      (`CodeFont.folderRevision`) and uses the same lookup as the interface font; not driven (no diff on screen in the runs).

## How it is followed (`app/own_files.rs:213-221`)
- [x] One watch: the fonts folder is a root of the settings follower's existing watch on the profile folder (`watch.rs` `Roots.fonts`),
      an OS mark, a 40 ms settle, then the callback; events outside config, themes and fonts do not wake. ffi: `watch::tests::only_the_file_the_themes_the_fonts_and_lost_events_call_for_a_look`.
- [x] One wake per burst, re-armed by `drain()`: ffi `the_fonts_folder_is_followed...` (add, drain, remove wakes again).
- [ ] The slow poll as the fallback: `check` (which asks `FontsFolder::moved()`) runs on the follower's 10 s / 2 s timer, the same code path as the
      config file's. Not shown alone: in run C the fonts folder was a symlink to a folder elsewhere and the font was still seen
      within 1 s (`X13-run-c.txt`), so the watch (not the timer) answered. Nothing was run with the watch failing.
- [x] No tick of ours: nothing polls on the 400 ms tick; the folder is read only on a mark or the follower's slow timer.

## Not like GPUI
- A skipped (broken) font file is not logged by the Swift app (`fonts.rs:107` warns); the list of skipped files is available from
  `fontCustomScan` for the picker only.
- GPUI's `FontCatalog::reload` refreshes the picker lists after a change; the Swift picker rescans when it opens
  (`FontLibrary.refreshCustom`), it does not reload an open picker.
