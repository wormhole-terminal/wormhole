GPUI's rule (app_state/profiles.rs first_free_ids, window_lifecycle.rs Workspace::rehome): ONE counter of terminal, split and window ids for every
profile, started past what every profile saved; a moved window keeps its ids and is saved into the target's database as it is. The Swift
`Windows::new` and `beside` do the same, so data written by this build cannot collide; what can is a profile database written before that
(each profile numbered from 1). GPUI would replace the other window's rows then; the previous lane refused. Now:
  - the target's DORMANT window with the same window, terminal or split ids is given new ids from the shared counter (a running terminal cannot
    change its id), rewriting the split layouts' panes, the sidebar groups and order, notes, tasks, pins, hidden-from-agents, no-text flags, host
    ids, claims and sealed text; refused only when that window is open (windows::rehome.rs, reissue.rs);
  - the moving window brings its notes, tasks, flags, the files each terminal changed and (when the target keeps text) the terminals' text;
  - the workspace is among the TARGET's windows afterwards (Shared::set_windows), which is what the hook server judges a request by (agent access);
    project trust and the usage meters follow too (ProjectService/UsageService.follow_profile, called by ProfileChipBinding.move).
