Live run of the Profile menu's "Open Window in" and "Move Window to": a --background instance, WORMHOLE_DATA_DIR=/tmp/Wormhole-swift-s-window-b,
WORMHOLE_SHELL=/bin/zsh, driven through the control folder (profile-new, profile-menu, sessions, saved-windows, profile-switch, quit). `profile-menu open|move N`
sends the same MenuCommand the menu bar's items send (ActionRouter.dispatch(.openInProfile(N)) / .moveToProfile(N)); N is the row's place in the profile list
(0 Default, 1 Work).

1. `profile-new Work`, `new`; `menus` shows Shell > Profile: Default (checked), Work, Open Window in > Default, Work; Move Window to > Work (enabled now: the
   menu state knows the window's own profile, `windowProfile`), New Profile..., Manage Profiles...
2. `profile-menu open 1` -> window 2 profile=work visible=true, terminal 3 (ids never repeat across profiles); window 1 stays profile=default and visible:
   Wormhole is still in Default, window 2 is the odd window (as the GPUI app's open_window_in_profile).
3. `profile-menu move 0` (window 2 in front) -> window 2 profile=default; saved-windows (Default's registry) lists windows 1 and 2.
4. `profile-menu move 1` (window 2 -> Work), `use-window 1`, `profile-menu move 1` (window 1, the last window of the profile Wormhole is in -> Work):
   Default is not left without a window: window 3 profile=default terminals=[4] opens; saved-windows lists window 3 only (1 and 2 left Default's database).
5. `profile-switch work` -> shown=[1, 2] parked=[3]; `profile-switch default` -> shown=[3] parked=[1, 2]; `quit`, relaunch (starts in Default: window 3 only), then
   `profile-switch work` -> windows 2 and 1 come back from Work's database with their terminals (1: [1,2], 2: [3]).
Rust: windows::tests::a_window_moved_to_another_profile_is_saved_there_and_gone_from_here (record, notes and frame move; the window stays among the live ones).
Not run: a click on the chip's own menu (a --background instance has no pointer; the chip's menu items are the same closures, wired in ProfileChipBinding).
